# AiFei · 视觉与体验需求书 v1.0

> 角色：审美需求方
> 范围：AiFei（恋爱记录站）全站视觉与交互
> 状态：已定稿，交由业务经理评估落地

---

## 1. 目标与原则

**一句话**：把这个站从「一份很长的文档」改成「一本有章节、会翻页的相册」，最后落在一封手写的信上。

三条原则，冲突时按顺序取舍：

1. **克制** —— 黑白、留白、细线。任何装饰先问「去掉会不会更好」。
2. **有节奏** —— 每屏都有「进来 / 停留 / 离开」，不允许一条长卷匀速度到底。
3. **有揭示** —— 内容不是「就在那里」，是「出现给你看」：遮罩、擦除、推镜、翻页。

---

## 2. 诊断：现在为什么「拉到底没有美感」

| 问题 | 表现 |
| --- | --- |
| 信息密度均匀 | 时间表 24 条、照片 24 张，每屏长得一样，眼睛没有落脚点 |
| 没有停顿 | 从顶滑到底是一次连续位移，没有「这一页结束了」的信号 |
| 没有揭示 | 文字和照片直接贴在文档流里，没有期待感 |
| 重力单一 | 只有纵向滚动，和浏览器默认滚到底没有区别 |
| 时间被压平 | 时间表等距排列：10 月 17 条、9 月 4 条，视觉上一样长 → 流水账 |

---

## 3. 骨架：一条长卷 → 一本有章节的书

| 章 | 内容 | 主交互 | 情绪 |
| --- | --- | --- | --- |
| 00 封面 | 名字 + 粒子 | 名字逐字浮现，天数滚动 | 安静 |
| 01 扉页 | 题记 + 在一起第 N 天 | 滚动一次 = 翻页 | 郑重 |
| 02 长河 | 时间表 | 可缩放的时间轴（见第 5 节） | 行进 |
| 03 相册 | 照片 | 编辑式版面，hover 灰度→彩色 | 慢 |
| 04 清单 | 待办 | 勾选手写划线 | 轻快 |
| 05 信 | 关于 + 结尾 | 逐段浮现，可盖章 | 收束 |

滚到底不是「结束」，而是「翻到下一章」。

## 4. 逐页需求

### 4.1 首页

- 现状：四屏等高色块，内容偏薄。
- 目标：开场字幕序列 —— 黑场 → 名字逐字出现（每字 60ms）→ 日期 `2026.09.01` → 天数滚动到当前值 → 「往下」提示。
- 细节：进入后 3 秒不滚动，画面要「呼吸」（粒子极慢漂移 + 天数微光）。

### 4.2 时间表（核心，见第 5 节专项）

### 4.3 照片页

- 现状：等宽瀑布流，往下滑就是一堵墙。
- 目标：**编辑式版面** —— 大小穿插（每 7 张出现一个跨两列的「主图」），照片出现时从下往上轻推 + 淡入，hover 时灰度→彩色 400ms。
- 长期目标（P2）：对开相册翻页。

### 4.4 待办页

- 勾选：一条手写感的线从左往右划掉（SVG `stroke-dashoffset`，350ms）。
- 勾满一类：纸面轻抖一下，不撒花。

### 4.5 关于页 / 信

- 逐段浮现，段间 120ms；结尾签名留空位，点击盖一个日期印章。

## 5. 时间表专项：从流水账到「一条可以缩放的长河」

### 5.1 概念

像地图一样**语义缩放**：缩小只剩大节点，放大才出现细节。不是把整页 scale 放大。

| 层级 | 视野 | 显示 | 情绪 |
| --- | --- | --- | --- |
| L0 全景 | 3 个月全宽，一屏看尽 | 年份 + 月刻度 + **只显示大节点** + 篇章带 | 看到整段故事 |
| L1 月度 | 约 1 个月 | 全部节点 + 短标题 | 看清疏密 |
| L2 事件 | 单条 | 大图 + 正文，其余淡出 | 停下来读 |

进入页面默认 **L0**：一整条河摊开，重要的点亮着。这一条直接解决「每次都要拉到最下面」。

### 5.2 视觉编码

| 维度 | 大节点（major） | 小节点（minor） |
| --- | --- | --- |
| 点 | 12px 实心 | 6px 空心 |
| 标签 | 常显，900 字重 | 仅 L1 出现，400 字重 |
| 图 | 有缩略图 | 无 |
| 动效 | 呼吸微光 | 无 |

- **位置 = 真实时间比例**（9 月短、10 月长，自然形成疏密）
- **同一天多条聚合成一个点**，角标显示条数（如 11-05 的 3 条）
- 空白期保留成留白 —— 空白也是叙事
- 篇章之间 1px 极淡分隔 + 一句短标题（`九月，开始聊天` / `十月，很远的地方` / `十一月，日常`）
- 右端永远有一个「现在」呼吸点

### 5.3 交互

| 动作 | 结果 |
| --- | --- |
| 进入 | L0 全景，节点依次点亮 |
| 双指捏合 / Ctrl+滚轮 | 以光标为锚缩放 |
| 拖拽 | 平移，带阻尼回弹 |
| 普通滚轮 | 横向平移（不做缩放，避免劫持） |
| 点击节点 | 700ms 推镜，底部抽屉展开该条（同日多条则列出） |
| 双击空白 / Esc | 回到 L0 |
| 键盘 ←/→ +/− 0 | 节点跳转 / 缩放 / 回全景 |
| 右上角 | `−` `+` `全部` + 当前位置（`2026 · 10月`） |

不迷路：任何时刻都能看到当前年月 + 底部迷你进度条（当前视野占全长的比例）。

### 5.4 内容规则

- 复用现有 `highlight` 字段作为 major（避免数据迁移与编辑页改动）
- 每个篇章最多 3 个 major —— 全是重点等于没有重点
- 篇章按月派生（不新增字段），标签在 `src/data/chapters.ts` 里改

### 5.5 验收

1. 进入 1 秒内看到全部节点分布，无需滚动
2. 任意月份可一次操作到达
3. 缩放时标签分级出现/消失，不重叠、不闪烁，文字不变形
4. 任何层级都能读到当前年月
5. 200 条数据不掉帧
6. 手机双指缩放顺滑，不与边缘返回手势冲突

## 6. 手感规范（全局）

| 项 | 值 |
| --- | --- |
| 缓动 | 只用 `expo.out` / `power3.out` / `cubic-bezier(.22,1,.36,1)` |
| 时长 | 文字 400–600ms，图像揭示 600–800ms，翻页 700ms；**上限 1.2s** |
| 层级 | 一屏最多 2 个动效并行；第 3 个等前一个结束 |
| 触发 | 滚动停止 120ms 后才算到位，防误触 |
| 降级 | `prefers-reduced-motion` 下全静态、内容完整可读 |

---

## 7. 不做的事

- 不加彩色、渐变、玻璃拟态、发光边框
- 不用 emoji 堆砌浪漫
- 不同时跑三个以上动效
- 不为了动效牺牲可读性与可访问性
- 不引入重型 3D（现有粒子够用）

## 8. 交付给业务经理的评估点

1. GSAP（现已全免费）vs 现有 anime.js：引入成本与收益
2. 横向长河在触屏上的手势冲突与降级方案
3. 翻页相册用 CSS 3D 还是 R3F
4. 中文字体子集化（得意黑 / 思源宋体）的体积与 FOUT
5. 现有 snap 滚动与新章节骨架如何合并
